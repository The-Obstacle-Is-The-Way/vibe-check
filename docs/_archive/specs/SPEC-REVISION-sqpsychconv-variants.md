2.  **Selected Primary**: `SQPsychConv_qwen-2.5` (highest quality, 16.29/18).
3.  **Selected Backup**: `SQPsychConv_gemma` (second highest, 16.14/18).
4.  **Cleanup**: Deleted bugged and lower-quality variants (`qwq`, `command`, `llama3`, `mistral`, `nemotron`).

**Recommendation**: Use `SQPsychConv_qwen-2.5` as the **single primary corpus**.

**Research-Backed Rationale**: Per 2025 synthetic data research, **model capability matters more than model diversity**. Using the highest-quality single model produces better results than ensembling multiple lower-quality models.

```
qwq Arrow MD5 (train): e3ff92d039b8ee12fa2023fc4d3abfb3
qwq Arrow MD5 (test):  e3ff92d039b8ee12fa2023fc4d3abfb3  # IDENTICAL

file_id overlap: 2090/2090 (100%)
```

### Impact

- HuggingFace displays 4.18k rows (incorrectly)
- Actually only 2,090 unique dialogues
- Train and test are literally the same data

Likely a dataset upload error by AIMH. All other variants have proper splits.

### 4.2 Why NOT Multi-Variant Ensemble?

Per 2025 research on synthetic data diversity ([arXiv:2410.15226](https://arxiv.org/abs/2410.15226)):

> "Synthetic data generated by more capable models usually present better diversity... Model capability matters more than heterogeneity in generation."

> "Mixing up the synthetic data generated by different base LLMs can also **slightly** improve diversity, leading to better performance."

**Key Finding**: The improvement from multi-model mixing is **marginal**. The research clearly indicates:
- **Investing in the highest-quality single model** is more important
- Multi-model ensembles provide only incremental gains
- Quality filtering on one good source beats unfiltered multi-source

### 4.3 Decision Matrix

| Approach | Pros | Cons | Verdict |
|----------|------|------|---------|
| **qwen-2.5 only** | Highest quality, proper splits, simple | Single source | **RECOMMENDED** |
| qwen-2.5 + gemma | Marginal diversity boost | 2× cost, complexity | Not worth it |
| All 7 variants | Maximum diversity | 7× cost, noise, diminishing returns | Over-engineered |
| qwq only | None | Bugged, lower quality | **AVOID** |

### 4.4 Final Recommendation

**Use `SQPsychConv_qwen-2.5` as the single primary corpus.**

This is the robust, research-backed approach:
1. Highest expert quality score (16.29/18)
2. Proper train/test split (no bugs)
3. Aligned with 2025 best practices: quality > diversity
4. Simpler analysis pipeline
5. No wasted API costs on lower-quality variants

### 4.5 When Multi-Variant WOULD Be Appropriate

Multi-variant would only make sense if:
- You're doing **cross-model consistency validation** (checking if different generators agree)
- You need **ablation studies** on model bias
- You're building a **meta-model** trained on multiple synthetic sources

For vibe-check's use case (scoring conversations → exporting labels), **single highest-quality source is correct**.

## 9. Research References (2025/2026 Best Practices)

### Primary Sources

1. **On the Diversity of Synthetic Data and its Impact on Training Large Language Models**
   - arXiv:2410.15226 ([link](https://arxiv.org/abs/2410.15226))
   - Key finding: "Model capability matters more than heterogeneity in generation"
   - Tested GPT-4o, GPT-3.5, Llama-3.1-8B, Mistral-7B
   - Conclusion: High-quality single model > multiple lower-quality models

2. **On LLMs-Driven Synthetic Data Generation, Curation, and Evaluation: A Survey**
   - arXiv:2406.15126 ([link](https://arxiv.org/html/2406.15126v1))
   - Quality filtering approaches: heuristic metrics, sample re-weighting
   - "Clean samples maintain similar predictions across different conditions"
   - Alpagasus: smaller curated dataset > larger uncurated dataset

3. **A Survey on Recent Advances in Conversational Data Generation**
   - arXiv:2405.13003 ([link](https://arxiv.org/html/2405.13003v1))
   - Framework: seed generation → turn generation → quality filtering
   - Quality filtering is more important than raw volume

4. **Multi-LLM-based augmentation and synthetic data generation**
   - ScienceDirect 2025
   - Tested Claude-3.5-Sonnet, Gemini-2.0-Flash, DeepSeek-R1
   - Finding: Different models excel at different tasks

### Key Takeaways for vibe-check

| Research Finding | Application to vibe-check |
|------------------|---------------------------|
| Quality > diversity | Use qwen-2.5 only (highest expert score) |
| Multi-model mixing = marginal gains | Not worth 7× cost |
| Curation > volume | Focus on filtering, not more sources |
| Cross-condition consistency | Use our deterministic resplit |

### Why This Matters

The original SPEC did not account for:
1. Multiple model variants in SQPsychConv
2. Quality differences between variants (12.57 to 16.29 range)
3. Trade-offs between single vs multi-model approaches

This revision corrects that gap with research-backed guidance.

## Appendix B: CSV Files Question

**Q: Where are the CSVs we saw before?**

The previous `test_sample.csv` and `train_sample.csv` were likely manually exported from Arrow files in a previous session. HuggingFace's `datasets` library downloads **Arrow format** by default, not CSV.

Arrow is actually preferred:
- Faster loading (columnar format)
- Type-safe (schema preserved)
- Memory-efficient

CSVs can be exported if needed:
```python
ds = load_from_disk("data/sqpsychconv/qwen-2.5")
ds["train"].to_csv("train.csv")
ds["test"].to_csv("test.csv")
```

But there's no need - Arrow works directly with our pipeline.
