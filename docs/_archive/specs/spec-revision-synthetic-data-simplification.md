# SPEC-REVISION: Synthetic Data Simplification

**Date**: 2026-01-02
**Status**: APPROVED - Ready for Implementation
**Scope**: Remove over-engineered privacy controls for synthetic data

---

## 1. Executive Summary

The current SSOT and implementation specs treat SQPsychConv dialogues as if they contain Protected Health Information (PHI). They don't. SQPsychConv is 100% synthetic data generated by LLMs doing therapist-client roleplay.

This document simplifies the project to reduce complexity, improve developer experience, and remove unnecessary overhead—while preserving controls that actually matter (cost & integrity).

---

## 2. The Core Insight

### What SQPsychConv Actually Is

| Fact | Source |
|------|--------|
| Dialogues are **100% LLM-generated** | SQPsychConv paper Section 3.1: "We use vLLM to host these models locally" |
| Generated by open models (QwQ, Llama 3.3, Mistral, etc.) | Paper Table 1 |
| Source questionnaires are anonymized | Paper: "the questionnaire dataset is pre-anonymized" |
| Published openly on HuggingFace | `AIMH/SQPsychConv_qwq` etc. |
| No real patient transcripts exist | Paper Ethics section: synthetic roleplay |

### What This Means

- **No HIPAA concerns** - there are no real patients.
- **No PHI** - the "clients" are LLM personas with fictional backgrounds.
- **No confidentiality obligation** - authors published openly without access controls.
- **License concern is about redistribution rights**, not privacy.

## 3. Current Over-Engineering (The "Privacy Theater")

### 3.1 In the SSOT (`docs/research/spec-vibe-check.md`)

| Section | Current Requirement | Problem |
|---------|---------------------|---------|
| 3.3 Logging Policy | "No raw transcript text in Checkpoint DB" | Synthetic dialogues aren't sensitive. |
| 3.3 SensitiveString | "Wrapper type that refuses to serialize to logs/JSON" | Unnecessary complexity for synthetic data. |
| 3.3 Evidence bounds | "≤3 snippets, ≤50 words, ≤400 chars" for **privacy** | Privacy rationale is wrong; limits are for **cost**. |
| 4.3 ScoringState | Removed `dialogue` from state to avoid checkpoint leakage | No leakage concern; makes state management harder. |
| 4.4 BatchState | Fan-out by `file_id` only, reload text ephemerally | Unnecessary I/O indirection. |

### 3.2 In SPEC-04 (`docs/specs/spec-04-juror-scoring-agent.md`)

| Section | Current Requirement | Problem |
|---------|---------------------|---------|
| 2.4 Security | `SensitiveString` + safe logging helpers | **Not implemented yet**, and should not be. |
| Goal #5 | "Never logs raw transcript text (data governance)" | Over-scoped. Debug logging is fine and useful. |

### 3.3 In SPEC-05 (`docs/specs/spec-05-consensus-orchestration.md`)

| Section | Current Requirement | Problem |
|---------|---------------------|---------|
| State Definition | `dialogue` removed, must reload via `file_id` | Adds node complexity for no benefit. |
| Node design | "Nodes must load dialogue text ephemerally" | Unnecessary I/O overhead. |

## 4. What Actually Matters

### 4.1 Keep These Controls

| Control | Why It Matters | Rationale |
|---------|----------------|-----------|
| **Evidence snippet length limits** | Prevents token explosion in prompts/outputs. | **Cost control** |
| **Token usage tracking** | Visibility into hidden reasoning tokens (GPT-5.2). | **Cost control** |
| **DAIC-WOZ restrictions** | Real academic license, no cloud egress. | **Legal compliance** |
| **SQPsychConv license check** | Redistribution rights unclear. | **Legal compliance** |
| **Deterministic resplit** | HF train/test may be identical. | **Data integrity** |

### 4.2 Abandon These Controls

| Control | Why Remove | Impact |
|---------|------------|--------|
| **SensitiveString wrapper** | No PHI to protect. | Avoids writing ~100 lines of boilerplate. |
| **No-dialogue-in-checkpoints rule** | Synthetic data isn't sensitive. | Simplifies LangGraph state inspection. |
| **Ephemeral text loading pattern** | Unnecessary I/O. | Simplifies node functions. |
| **Privacy framing in docs** | Misleading. | Clearer documentation ("Operational Hygiene"). |

## 5. Approved Changes

**Section 3.3 - Rename and Reframe**

```markdown
### 3.3 Logging & Observability Policy (Operational Hygiene)

> **Note**: SQPsychConv is synthetic data with no PHI. These guidelines exist for
> **operational hygiene** (cost control, audit trails), not privacy compliance.

| Artifact | Recommended Content | Rationale |
|----------|---------------------|-----------|
| Checkpoint DB | File IDs, scores, entropy, status, token usage, **dialogue text** | Full state for debugging. |
| Evidence fields | Bounded snippets (≤50 words) | Cost control (prevents token explosion). |
```

```python
class ScoringState(TypedDict):
```

## 6. What Stays the Same

These are NOT changing:

1.  **DAIC-WOZ restrictions** (Section 3.2) - Real legal constraint.
2.  **SQPsychConv license uncertainty** (Section 3.1) - Redistribution question remains.
3.  **Deterministic resplit** (Section 3.4) - Data integrity concern is real.
4.  **Evidence length limits** - Keeping the limits (`MAX_EVIDENCE_SNIPPET_WORDS = 50`), just reframing rationale.
5.  **Token usage tracking** - Cost visibility is valuable.
6.  **PydanticAI requirement** - Framework choice is sound.
